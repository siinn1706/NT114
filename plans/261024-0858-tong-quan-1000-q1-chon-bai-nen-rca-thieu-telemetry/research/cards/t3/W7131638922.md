## Problem
Localize the root-cause microservice of performance anomalies in microservice IoT apps on edge-cloud systems, cutting localization time versus centralized graph-based RCL without losing accuracy (Abstract; SI).

## Assumptions
- Placement uses communication-aware placement at least as a secondary objective, so anomalies mostly stay inside a cluster (SI; SV).
- Topology graph is built from traces and deployment info; anomaly detection runs on all metrics (SII-C; SIII).
- No bidirectional frequent inter-cluster communication (SV).

## Method (data and control flow)
- Per edge device BIRCH flags anomalous metrics (beta 0.07) (SIII; SIV-A).
- Alg 1 merges per-device clusters whose communication weight exceeds tau; Alg 2 builds per-cluster subgraphs with shadow nodes (SIII-B).
- Anomaly score = BIRCH-cluster correlation + incoming-edge latency correlation (Eq 1-3, SIII-A); PPR per cluster (SII-C).
- Cross-cluster: one-time exchange of average anomaly score (JXP-style) and ranking-vector aggregation (Eq 4, SIII-C).

## Modalities
Metrics (node and edge scores) plus traces (topology). Logs unused (SII-A; SIV-A).

## LLM role
None.

## Datasets/splits
MicroCERCL public benchmark, 81 microservices, 383 scenarios used: 237 SockShop-root (SH) + 146 Hipster-root (HH); 311 single-cluster, 72 multi-cluster. No train/test split (unsupervised; TPE tunes tau, alpha, eps on the same scenarios) (SIV-A; Tab IV).

## Baselines
Own centralized PPR (re-run); MicroCERCL GNN numbers copied from its paper, not re-run (SIV-B, Tab II).

## Metrics (+denominator)
Acc@k (k=1,2,3,5,10), MAR, MRR over scenarios; average and total time-reduction percentage with formulas (SIV-B). Denominator = 146 HH or 237 SH scenarios.

## Main results
- HH Acc@1 0.5616 vs centralized 0.4315, MRR 0.7295, time -17.41% avg / -21.34% total (Tab III).
- SH Acc@1 0.6076 vs 0.4979, MRR 0.7733, time -33.22% / -33.59% (Tab III).
- Single-cluster time gain 23-34%; multi-cluster 2.77-28.79% (Tab IV).

## Cost
CPU-class PPR/BIRCH; run on Spartan HPC; no training; no API tokens (SIV-A; SII-D). Wall-time numbers are not given in seconds, only percentages (Tab III).

## Limitations
- Needs communication-aware placement; does not generalize to frequent bidirectional inter-cluster traffic (SV).
- Gains shrink in cross-cluster cases (SIV-C, Tab IV).

## Threats
- One benchmark, no repeats or significance test; the 383 scenarios were selected for "adequate diversity" without a stated rule (SIV-A).
- tau, alpha, eps tuned on the evaluated scenarios, with no held-out set (SIV-A).
- Time measured on one HPC cluster; edge-device latency is argued, not measured (SIV-D).

## Counter-evidence
- GNN (MicroCERCL) has higher HH Acc@1 (0.632) than the decentralized method (0.5616); parity is claimed only against the authors' own PPR (Tab II, Tab III).
- Accuracy gain attributed to "noise reduction" has no ablation; no ablation of the new anomaly scoring versus clustering (SIV-B).
- HH multi-cluster average time reduction is only 2.77% on 41 scenarios (Tab IV).
- Centralized PPR already reaches Acc@10 of 1.0 on HH, so top-k saturates (Tab II).
