## Problem
- Rank service, pod or node root causes for a failed request in microservices; failure = entry-span latency above 100x normal average (Sec. II-A, II-C).
- Targets two LLM weaknesses: context explosion and serial shallow reasoning (Sec. I; post-mortem of 100 failed CoT cases: 43 evidence dilution, 57 shallow, Sec. III-B).

## Assumptions
- One unique root cause per episode at service, pod or node level (Sec. II-B). Traces must cover the propagation path; logs and metrics must carry signal near the failure time (Sec. VI (4)).

## Method (data flow and control flow)
- Data: Trace Tool returns child spans (Eq. 2); Metric Tool returns metrics breaching n-sigma (n=3) inside +/-delta=60 s (Eq. 3-4); Log Tool returns heuristically filtered logs (Eq. 5) (Sec. IV-A).
- Control: one Dedicated Agent per span; self-state verification then evidence consolidation of child outputs (Eq. 6-7, Fig. 5-6); Agents Pool K=100 caps parallelism (Eq. 8); Root-Level Diagnosis Report plus Global Evidence Graph go to a Diagnosis Synthesizer that outputs the ranked list (Eq. 9-10) (Sec. IV-B, IV-C).

## Modalities
- Traces (backbone), metrics, logs as tool evidence (Sec. IV-A). AIOps2022 logs have no SpanID so per-span logs are absent there (Appendix C).

## LLM role
- Claude-3.5-Sonnet default and Qwen-3.6-Plus, both closed APIs; the same backbone serves every agent and the synthesizer (Sec. V-A.4, Table I). Number of calls per trace is not reported; the code makes at least two calls per span (coordinator.py inspect_trace).

## Datasets/splits
- AIOps2022 (7 services, 44 pods, 6 nodes; subsets A,B,Gamma,Delta,E,Z), Augmented-TrainTicket (Nezha, 41 services), RCAEval RE2-OB (Sec. V-A.1). Training-free method, so no split; hyperparameter tuning data is AIOps2022-A (Sec. V-F, Fig. 8).
- Evaluated faults come only from the README: 66 (AIOps2022), 17 (TT), 90 (RE2-OB) (README Sec. 7); paper gives no |A|.

## Baselines
- Non-LLM: CRISP, TraceContrast, TraceRCA, MicroRank, RUN, MicroScope, CausalRCA, Eadro, Nezha, BARO; LLM: CoT, RCAgent, mABC, GALA (Sec. V-A.2, Table I). Backbone used for the LLM baselines is not stated.

## Metrics (+denominator)
- Recall@k and MRR = (1/|A|) sum 1/Rank_i over fault instances A, rank infinite if outside top-10 (Eq. 11, Sec. V-A.3). Pod answers count as correct if the service matches. README Sec. 6 takes the best rank across all error traces of a fault.

## Main results
- MRR AIOps/TT/RE2-OB: Qwen-3.6-Plus 73.24/86.47/71.03, Claude 69.73/74.08/62.97; best baselines mABC 58.05 (AIOps), Nezha 90.37 (TT), GALA 58.93 (RE2-OB) (Table I).
- Paired Wilcoxon p<0.05, MRR p=0.012 against mABC and GALA (Sec. V-B). Ablation: RLDR-only beats GEG-only by 7.29, full adds 5.54 (Fig. 7, Sec. V-E).

## Cost
- 41.43/59.55/49.79 s per query vs 85.77-195.34 s for LLM baselines; BARO 0.13-0.71 s (Table II). Server 24 CPU, 400 GB RAM; API tokens and dollars not reported (Sec. V-A.4).

## Limitations
- Needs trace coverage; without traces it degrades to a ReAct agent with more cost and lower accuracy (Sec. VI (1)).
- Unsampled or uninstrumented services create blind spots and misattribution to neighbours (Sec. VI (2)). Hallucination and LLM cost (Sec. VI (3)).

## Threats
- Baselines partly re-implemented and tuned by the authors; three benchmarks only (Sec. VI first paragraph).
- Dataset-keyed prompts and known-service name normalisation in coordinator.py (repo, 2026-10-25) are not described in the paper.

## Counter-evidence
- Nezha beats RCLAgent on TT MRR (90.37 vs 86.47/74.08) and BARO beats it on RE2-OB R@3/R@5/R@10 (92.22/100/100 vs 80.00/86.67/100) (Table I; Appendix C).
- Open backbones are far weaker: Llama-3.1-70B MRR 7.09-19.42, DeepSeek-R1-Qwen-32B 36.13-65.13 vs Claude 54.88-88.67 (Table III); nothing below 32B tested.
- Best-of-traces aggregation and 66 of 263 listed AIOps faults (README Sec. 3.1, 6, 7); LLM-baseline backbone unstated (Sec. V-A.2). Speedup quoted as 1.49x in Sec. V-C and above 1.75x in Sec. I.

## Missing-telemetry handling
- Qualitative only: no-trace and missing-span cases are predicted to degrade (Sec. VI (1)-(2)); no controlled drop of any modality; natural absence of logs on AIOps2022 (Appendix C). NT114 conditions no_trace and blind_root map directly to the stated failure modes.

## Core kept under single-LLM
- The trace-graph decomposition into bounded span-level contexts with evidence consolidation and a final synthesis step runs with one model called many times. It does not need multiple models, but the call count is per span and the quality depends on a strong backbone (Table III).
