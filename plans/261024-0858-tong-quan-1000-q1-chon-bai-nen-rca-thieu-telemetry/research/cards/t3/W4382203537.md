## Problem
Given a failure alert, rank the root cause instance (Task 1) and classify the failure type (Task 2) from traces, logs, metrics and deployment data; robust to imbalanced failure types (Abstract; S2.3).

## Assumptions
- Labelled historical failures exist for each system (160 for D1, 80 for D2); retrain when a new service group appears (S6.1, S6.3).
- Alert/anomaly time is given by a trigger (S4.1, Fig. 5).

## Method (data and control flow)
- Events: 3-sigma on metrics and numeric trace fields, count jumps on categorical trace fields, Drain log templates hashed to ids; events keyed by timestamp and instance and serialised per instance (S4.2, p.4).
- Embedding: fastText supervised on relabelled event sequences; augmentation replaces one event by its nearest neighbour until each class has about 1000 samples, then retrain (S4.4.1, p.5).
- Graph: nodes = instances (mean of event vectors); edges = trace caller-callee both ways plus co-deployment (S4.3, p.4).
- GNN: TAGConv, max-pool readout, softmax over service groups (Task 1) and failure types (Task 2), joint loss (S4.3, S4.4.2, p.5-6).
- Ranking: take the predicted service group, order its instances by number of anomalous events (S4.4.2, p.5).

## Modalities
Trace, log, metric plus deployment data (S2.1, p.2).

## LLM role
None (fastText + GNN) (S4.2-S4.3).

## Datasets and splits
- D1 GAIA/MicroSS simulation: 10 microservices + MySQL/Redis + 5 hosts, 17 instances, 5 failure types, 160 train / 939 test; D2 bank system: 18 instances, 80 train / 79 test, private; both split by start time (S5.1.1, Table 2, p.6).

## Baselines
Task 1: MicroHECL, MicroRank, AutoMAP, MS-Rank, PDiagnose; Task 2: Cloud19, LogCluster, CloudRCA; parameters per their papers (S5.1.2, p.6-7). All 2018-2021.

## Metrics and denominators
A@k = share of test failures whose root cause instance is in the top-k, |A| = number of test failures; Avg@5 = mean of A@1..A@5; Task 2 weighted precision/recall/F1; 5 repeats averaged (S5.1.3-S5.1.4, eq. 5-6, p.7).

## Main results
- D1: A@1 0.419, A@3 0.813, A@5 0.914, Avg@5 0.750; failure-type F1 0.839 (Table 4, Table 3, p.7-8).
- D2: A@1 0.646, Avg@5 0.790 in Table 4 but 0.76 in abstract and Fig. 8; F1 0.800 (Table 4, Fig. 8, Table 3, p.7-8).
- Avg@5 at least 0.13 above single-modal baselines and 0.18 above PDiagnose (S5.2, p.7).
- Without augmentation D2 Avg@5 falls to 0.471 (Table 4, p.8).

## Cost
CPU only (12 x Xeon E5-2650 v4, 128 GB, no GPU); online 10.95 s (D1) and 3.26 s (D2) per case, offline 11.02 s and 3.59 s (S5.1.4; Table 5, p.8).

## Limitations (as stated)
Datasets small and failures simpler than industry; needs labelled failures and retraining for new service groups; accuracy drops without metrics (S6.1, S6.3 p.10; Table 6 p.9).

## Threats (as stated)
Two small datasets; limited failure types in D1 (S6.3, p.10-11).

## Counter-evidence
- Table 6 compares DiagFusion on all modalities (0.419/0.813, identical to the whole-D1 result) with the 62 metric-less cases (0.274/0.661); different case sets, so the drop is confounded (S6.2, Table 6, p.9; Table 4).
- The claim "outperforms all variants" fails at cells: D1 C5 A@1 equals 0.419; D2 C3 A@1 0.671 > 0.646 (S5.3, Table 4, p.8).
- Abstract and Fig. 8 say D2 Avg@5 0.76; Table 4 says 0.790 (Table 4, Fig. 8, p.7-8).
- Only 2018-2021 baselines; no Eadro or other 2022+ learned model, no significance test (S5.1.2, S5.1.4, p.6-7).
- A later paper reports that an MLP matches GNN-based frameworks on five datasets, weakening the GNN contribution (ICWS 2025, W4414648091; see prior csv).
- D2 results cannot be re-run (private) (S5.1.1, p.6).

## h1-compat
yes (conditional): top-5 instance ranking, softmax over service groups gives top-1 group confidence; within-group order is an event count with no calibrated score (S4.4.2; eq. 5-6).

## Missing-telemetry handling
Observational only: on 62 D1 cases lacking metric data DiagFusion keeps A@1 0.274 / A@3 0.661 vs PDiagnose 0 / 0.161; claims any two modalities work, not tested (S6.2 Table 6; S6.3 p.9-10). No injected per-modality drop.

## Core kept under single-LLM
Non-LLM core composes with one LLM: the GNN supplies top-5 instances, group probability and failure-type posterior as evidence; the LLM reranks or explains. Training needs about 80-160 labelled failures per system, which a zero-training single-LLM MVP lacks; no LLM evidence in the paper.
