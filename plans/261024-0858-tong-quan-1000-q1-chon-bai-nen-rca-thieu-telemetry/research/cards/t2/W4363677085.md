## Question
Find sets of requests whose RPC execution-time combinations explain latency degradation (Latency Degradation Patterns, LDPs) to help performance debugging (Abstract, Sec.1).

## Method
Search-based: multi-objective genetic algorithm (Pareto: precision, recall, latency dissimilarity), search-space built with Mean Shift, precomputation of predicate checks, decision-maker heuristic picks one pattern set (Sec.3-4). Output = request clusters plus RPC-time predicates, not a ranked service list.

## Data and systems
E-Shopper (7 unique RPCs, 5 services) and Train Ticket (14 RPCs, 9 services); 700 datasets generated by load testing with injected artificial delays (Sec.5.1, 5.3, 5.4). No public pre-existing dataset used; authors state none suitable (Sec.5.9.3).

## Modalities
Distributed traces only (Zipkin / Jaeger RPC durations). No logs, no metrics.

## LLM
None.

## Baselines
K-means, hierarchical clustering, KrSa (2013), CoTr (2021), DeCaf (random forest, 2019) (Sec.5.2).

## Metrics
Qprec, Qrec, QF1 over requests assigned to injected delay combinations, with explicit set-cardinality denominators (Sec.5.3, Eq. 11-13); IQR for stability; runtime (RQ4). Wilcoxon + Cliff's delta, 20 runs per technique (Sec.5.4, Table 2).

## Main results
DeLag beats all baselines in at least one case study, p <= 0.05 with non-negligible effect; Train Ticket 3 of 5 baselines significant; KrSa not significant there (Sec.5.4, Table 2). DeLag 22% / 17% faster than 2nd/3rd best on largest data (Sec.1, RQ4). Mean F1 IQR approx 0.86-0.93 (E-Shopper), 0.85-0.95 (Train Ticket) (Sec.5.4). Table 2 text is readable.

## Artifact availability
Replication package: zenodo 10.5281/zenodo.7785784 and GitHub SEALABQualityGroup/replication_delag (reference [52], Sec.5.10). License and run instructions not verifiable from the text. Compute: dual Xeon 40 cores, 80 GB RAM, no GPU (Sec.5.1.3).

## Limitations / failure modes
Only two LDPs per scenario; injected delays on critical-path RPCs; lab workloads (86% of SLO violations assigned to injected delays); small RPC counts; real-world generality unproven; high-ordinal categorical attributes not supported (Sec.5.9, Sec.6). Genetic-algorithm parameters tuned on 5 datasets only (Sec.5.9.1).

## Missing telemetry
Not handled: trace-only, assumes complete distributed tracing ("prerequisite", Sec.5.9.3); RQ3 tests noise from non-critical RPC time variation, not absent data.

## Fit to NT114
Same Train Ticket system, but the task is latency-pattern mining, not root-cause service ranking; F1-score is not AC@k/MRR. Weak base-paper candidate; useful as a trace-only baseline idea.
