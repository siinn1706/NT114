## Question
Diagnose anomalies of four DBMS (Oracle, MySQL, PostgreSQL, DM8) like a DBA, using expert experience stored in a graph.

## Method (S4-6)
Heterogeneous experience graph built semi-automatically from documents; 800+ anomaly models over metrics (directly alerted and implicitly correlated); two-stage graph evolution and ADF dynamic thresholds; a reasoning LLM gets graph paths plus metrics in a 5-part prompt <S_a,S_l,S_m,S_e,S_o> and writes a report with up to 5 causes and fixes.

## Data and systems
In-house anomalies on 4 DBMS: 178, 114, 127, 139 scenarios; ground truth from DBA reports (S7.1, Table 4). Not microservices.

## Modalities
Metrics (Prometheus) primary; logs and baselines as context; knowledge graph.

## LLM
DeepSeek-V3, R1-32B, R1-671B as report writers; 32B via Ollama on one RTX 3090; closed LLMs excluded for privacy (S7.1).

## Baselines
Rule-based tool + DBA, LLM-only (R1 32B/671B), ChatDBA, D-Bot (PostgreSQL only) (S7.1, Table 5).

## Metrics
Precision, F1, Accuracy (Ac - sigma*Aw)/Aa with sigma 0.1, human evaluation HEval with 3 weighted criteria (S7.1). No repetition or test.

## Main results
Table 5: DBAIOps R1-671B Accuracy 1.00/1.00/0.91/0.82 and HEval 0.91/0.98/0.88/0.95 on Oracle/MySQL/PG/DM8; D-Bot on PG HEval 0.35-0.50. Table 6 (Oracle, R1-32B): removing ADF or graph evolution drops Accuracy to 0.73/0.63.

## Limitations / failure modes
None stated by authors. Baseline failure: LLM-only hallucinates evidence (S7.4).

## Missing telemetry
Not studied. Graph evolution fills missing knowledge paths, not missing metrics.
