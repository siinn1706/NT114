# W7140089134 - LORIN: Log Retrieval With Intelligent Decomposition and Narrowing

- Version read: published journal (IEEE Access 2026), 21 pp; text sha256 08866ae62ca8c241a00879907e2d854b752ba5d4af1125bc53e8018b054e2348
- Reader r1; F total 14 (F1 2, F2 0, F3 6, F4 3, F5 2, F6 1); t2_gate 0
- Question: given a bug report query, recommend contiguous log line ranges a developer should review (log-range recommendation, LRR). Not microservice RCA.
- Method: Stage 1 teacher-student masked autoencoder anomaly filter on sliding windows (w=100, 95th percentile) feeding a FAISS index; Stage 2 planner-retriever-grader-generator RAG with query decomposition, confidence grader (tau 0.6), replanner (Sec III, Fig 2).
- Data and systems: 30 AOSP bug reports (Google Issue Tracker or reproduced in AOSP 13 emulator), avg 10,445 lines, GT ranges by author annotation, kappa 0.806 (Sec IV.A, Table 2).
- Modalities: single (Android logcat text).
- LLM: Gemini 2.5 Flash API for planner, grader, generator; bge-multilingual-gemma2 and all-mpnet-base-v2 embeddings; 2x RTX 4090 (Sec IV.B). No LLM comparison.
- Baselines: KeywordSearch, BM25, DenseRetrieval, HyDE, ColBERTv2, Hybrid (Sec IV.C); ablations naive/+planner/+evaluator/full/reactive. No RCA baselines (authors say none exist).
- Metrics: coverage |P and G|/|G|, IoU, output volume |P|/T, latency (Sec IV.D, Eq 4-6). Not AC@k/MRR.
- Main results: coverage 66.4% vs best baseline 31.2% (Hybrid), IoU 17.8% (Sec V.C, Table 5); buffer 0-500 gives coverage 66.4 to 89.9%, IoU 17.8 to 4.8% (Sec V.A, Table 3); Friedman p<0.001 (Sec V.F); hallucinated range misalignment 45.8% to 4.2% on 24 ranges (Sec V.D, Table 6); latency 224.6 s/query.
- Artifacts: github.com/ehdgml1/lorin-proto stated (Sec I); license and run instructions not stated in text; GT dataset release not stated.
- Limitations: single domain, 30 cases, no user study, no LLM backend comparison, Case 1 coverage 9.6% with dispersed GT, low IoU (Sec VI.A-B, VII).
- Missing telemetry: not addressed; only logs, and Stage 1 deliberately discards "normal" log windows to shrink the search space.
- Note: relevant only as a log-narrowing/RAG idea for a log modality; fails the RCA gate.
