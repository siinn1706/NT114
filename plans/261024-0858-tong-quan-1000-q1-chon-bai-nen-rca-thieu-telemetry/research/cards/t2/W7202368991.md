## Question
Zero-shot, training-free service-level RCA via Grover amplitude amplification, avoiding the training time of AI-based RCA (Abstract, SI).

## Method
Per-service summed API response time vs baseline sum -> sigmoid (k 0.1, Tth = mean of normal load) -> qubit amplitude; Z-gate oracle plus Grover diffusion; 1024 shots; service with highest P(|1>) is root cause. One qubit per pod; METIS partition proposed for scale (SIII-B.3, SIII-C, SIII-D, SIV).

## Data and systems
OpenTelemetry Astronomy Shop (5 of 16 services expose response time; 3 usable for single-fault tests), HipsterShop (Online Boutique, 5 services), TrainTicket (63 pods). Faults via flagd or ChaosBlade (CPU, memory, network) (SV-A, SV-H.1, SV-H.4). Own-generated workloads, not released.

## Modalities
Aggregated API response time only (SIII-C.2). Logs/traces/metrics mentioned only as background (SII-A).

## LLM
None. Quantum simulator (Qiskit Aer, CPU up to 25 qubits per Table 4 caption; GPU for larger) and IBM Heron r1 QPU (SV-B).

## Baselines
epsilon-Diagnosis, CausalRCA, TraceAnomaly, official code re-run; baselines get sparse metrics (authors admit this hurts CausalRCA) (SV-H.3, SV-H.6).

## Metrics
Precision/recall (single fault), HR@n n=1,3,5 over 20 runs, execution time (SV-D, SV-H.5).

## Main results
- Single fault recall: C/O 20/20, P/C 18/20, R/C 19/20; precision about 0.95 (SV-D.1, Table 5).
- Claims +36% CPU, +44% memory, +25% network vs best baseline on HipsterShop (SV-H.6 text; Table 7 body not in text).
- QPU: TrainTicket HR@1 0.70 (63 qubits, 71.2 s); 133-qubit random stress run 189 s, no accuracy (SV-I).
- 98.04 s GPU TraceAnomaly vs 71.21 s QPU QROOT (SV-H.6).

## Limitations / failure modes
Coupled services (P/C vs R/C) have margins 0.008-0.07 (SV-E, SVI-E); aggregation can dilute single-API faults (SVI-G); fixed k and Tth, unknown anomaly count M, NISQ noise, qubit per pod bound (SVI-A,B,F).
