## Question
Given a known fault time, locate the failed container/node and the failed KPI in a real operator microservice system (AIOps Challenge 2020).

## Method (SII.B-D)
Trace tree matching to "standard trees", per-node latency matrix, RPCA anomaly score gives candidate nodes. Candidates' KPIs are scored by an SLI vote of Isolation Forest, One-Class SVM, LOF and 3-sigma over six hand-made features. No candidate indicator fired means a network fault. Output: ranked indicators.

## Data and systems
AIOps Challenge 2020 sample batch plus 3 test batches (11, 13, 11 faults and the 11-fault sample); a private-cloud operator system (Zhejiang Mobile); topology, call chains, esb business KPIs, OS/DB/container KPIs (SII.A, SIII.A).

## Modalities
Traces (invocation chains) and metrics (KPIs). Topology table (cmdb) used as prior.

## LLM
None.

## Baselines
IF, LOF, One-Class SVM as single-indicator detectors only (SIII.B, Table 8 text). No other RCA method.

## Metrics
Challenge score: 1 point if first candidate right, 0.2 if second, divided by number of faults (SIII.B); "top-two precision 91.3%" (SI).

## Main results
Average score 0.8304 over four batches vs IF 0.6784, LOF 0.5657, OCSVM 0.5913 (SIII.B). Per-batch Tables 5-7 and Table 8 are images (not in text).

## Artifact availability
No code statement. Data said to be downloadable at iops.ai (SII.A, unverified).

## Limitations / failure modes
Needs given fault time; no esb anomaly detection; offline only (SIV). One fault root was outside the organizers' fault list (flyremote, SIII.A).

## Missing telemetry
Not studied; the only handling is the network-fault fallback when no indicator of a node fires. No controlled removal of trace or metric.
