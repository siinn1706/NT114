## Question
Localize faulty service and root-cause metric from monitoring data with gradient-based causal structure learning instead of PC/GES/LiNGAM (Abstract, SI).

## Method
DAG-GNN (VAE with GNN, augmented Lagrangian, eta 10, gamma 0.25) learns a weighted metric DAG; reverse edges, abs weights, PageRank (alpha 0.85) ranks metrics (SIII-B, SIII-C). Runs after an anomaly is detected; detector itself not described.

## Data and systems
Sock Shop on Kubernetes (1 master, 3 workers, 4 vCPU/16 GB each), Prometheus every 5 s, Locust load; Pumba injects CPU hog, memory leak, network delay per service, 5 min each (SIV-A.1-3).

## Modalities
Metrics only: service latency plus container CPU, memory, disk, network (SIV-A.3, Table II). No traces or logs.

## LLM
None.

## Baselines
PC, GES, LiNGAM each combined with PageRank (causal-learn defaults) (SIV-A.4). No other published RCA system.

## Metrics
AC@k (eq. 10, denominator min(k,|Vrc|)), Avg@k (eq. 11); AC@1, AC@3, Avg@5 reported; 10 runs averaged; ANOVA plus pairwise t-test (SIV-A.5, A.6).

## Main results
- Coarse, faulty service: avg Avg@5 0.5815 vs LiNGAM 0.5143, avg AC@1 about 0.2 (SIV-B.1, Table III).
- Fine, metric in faulty service: avg AC@3 0.719, Avg@5 0.6681 (+9.43%); ANOVA p 0.0013 (SIV-B.2, Table IV).
- All metrics in all services: avg rank of root-cause metric about 13 (SIV-B.3, Fig 10); t-test p 0.0335 vs LiNGAM.

## Artifact availability
"All codes and data" in GitHub AXinx/CausalRCA (SIII intro, footnote 7; printed as 'CausalRCA code.git'); license and run guide not checkable from text.

## Limitations / failure modes
Single testbed, three fault types, fixed 5 min windows (SIV-C). All-metric localization weak; time lags ignored; scalability untested (tens of seconds on small app); idea to add trace/log and personalized PageRank (SV).

## Missing telemetry
Not addressed as a robustness test. Only varies input scope (service latency only vs resource metrics vs all metrics), SIV-B.1-3.
