# Leveraging Deep Learning for Fault Detection and Localization in Distributed Systems
- openalex_id: W4412375007; version read: publishedVersion (full text); text sha256: ba0406bd81b860bd751593a473455f19d9389f0ff3e223e4d0892b5cae410320
- Question: which deep model best does 'fault localization' from logs on LogHub.
- Method: log parsing, TF-IDF/Word2Vec, min-max, then LSTM/GRU/CNN/LSTM+CNN/Autoencoder+LSTM trained to reconstruct/regress; 5-fold CV (SIII.B-D). Benchmark, not a new architecture (SIII.C).
- Data and systems: HDFS, OpenStack, Spark, Hadoop, BGL from LogHub, 80/20 split (SIII.A, Table 2). No microservice system.
- Modalities: logs only.
- LLM: none.
- Baselines: only the five own architectures; literature comparison is qualitative (SIV.D, Table 6).
- Metrics: MSE, MAE, R2 (SIII.D Step 3); paired t-test, Wilcoxon, 95% CI (SIV.E, Tables 7-9).
- Main results: CNN best, HDFS MSE 0.00002, R2 0.996 (Abstract, SIV.B, Table 5).
- Artifact: no code; LogHub public; Colab T4 / laptop CPU (SIII.C.6).
- Limitations: false positives on Spark/Hadoop, sequential-model variance, weak autoencoder (SIV.H).
- Missing telemetry: not handled; only a noise-cleaning step for bad lines (SIII.B.1). Output has no component identity, so it is not localization.
