## Question
Detect performance anomalies robustly with few labels and localize the system-metric root causes in a cloud application (Abstract; S1).

## Method
Metric selection by correlation analysis / PCA (S3.1); deep ensemble of base detectors (IForest, KNN, LOF, OCSVM) trained weakly-supervised with an MLP/LSTM head, multi-step prediction (S3.2); root cause: PC-algorithm dependency graph over selected metrics and anomaly label, then random walk on the DAG (S3.3, Algorithm 1).

## Data and systems
In-house Hyperledger Fabric DApp on Azure VMs monitored with Prometheus, I/O stress injected with stress-ng, 12 h, 3237 samples, 229 metrics (S4.1.1); public SMD server dataset for detection only (S4.1.2).

## Modalities
System-level resource metrics (CPU, memory, disk, network); one anomaly indicator (transaction failures).

## LLM
None.

## Baselines
Detection: base learners and linear ensembles, MLP-augmented variants (S4.3, Tables 6-7). Localization: PC vs ANM graph construction only (S4.4.2, Fig. 12).

## Metrics
F1 with precision/recall (Eq. 5); AC@k = hits in top k over min(k,|Vrc|) and Avg over k (Eq. 7-8, S4.4.1).

## Main results
- Detection: deep ensemble best F1 and robustness rank on both datasets (Tables 6-8); F1 above 0.8 predicting 4 minutes ahead (Abstract).
- Localization (Table 12): AC@1 = 1 on all 5 anomaly points, Avg 0.73-1.0, under 1 s; PC beats ANM (Fig. 12).
- Table 10: 10% labels give similar F1 to 50%.

## Limitations / failure modes
Base learners chosen manually; hyperparameter tuning pending; linear PC dependency graph, nonlinear relations (graph autoencoder) left to future work; only resource metrics used (S5). RCA tested on 5 injected I/O anomalies of one system, so ground truth is easy.
