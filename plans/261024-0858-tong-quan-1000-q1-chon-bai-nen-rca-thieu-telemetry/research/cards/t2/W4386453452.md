# A 2-Phase Strategy for Intelligent Cloud Operations
- openalex_id: W4386453452; version read: publishedVersion (full text); text sha256: f24e9bdf170562b505edb31e05e899f993e4b37b0b5255fdec5292f015f8797b
- Question: detect anomalies in an elastic group of cloud instances and recommend the corrective action.
- Method: phase 1 MADI/NSRF anomaly detection on aggregated metrics; phase 2 XGBoost classifier on spatially aggregated + raw instance metrics predicts action per instance (SIII.A-B, SIV.E).
- Data and systems: OpenStack Yoga on 3 hosts; distwalk synthetic app and Cassandra, injected stress/fault/saturation with stress-ng (SIV.A-D). Not microservices.
- Modalities: Monasca CPU and disk I/O metrics (1-min), plus operator action history as labels.
- LLM: none.
- Baselines: none; quantitative comparison deferred to future work (SV).
- Metrics: accuracy, ROC-AUC, per-class precision/recall/F1, confusion matrices (Tables 1-4, Fig. 7-10).
- Main results: AD AUC 0.97/0.94, accuracy 90.34%/87.50%; classifier accuracy 96.15% (synthetic) and 98.75% (Cassandra) (SIV.E, SV).
- Artifact: companion GitHub repo [40], open-source license claimed (Abstract, SI.A); trains <10 s on CPU (SIV.E).
- Limitations: only two metrics, few fault types, no comparison, drift/retraining, labelled data (SV).
- Missing telemetry: not handled; single metric modality, no degradation experiment.
