## Question
Learn the service-level fault-propagation DAG per 180 s window from metrics with few labeled graphs; generalize to unseen fault locations.

## Method (SIV)
Transformer metrics encoder, graph autoencoder, per-edge scoring; losses: edge CE, reconstruction, acyclicity (NOTEARS-style), fault-location CE, disentanglement (removes fault-specific features); labels only for a subset of windows.

## Data and systems
Dataset A: OpenTelemetry Demo v1.0.0, 12 services, CPU-hog on each, 417 batches. Dataset B: TrainTicket, 41 services, CPU-hog in 4 services x 3 runs, 348 batches. Ground-truth graphs derived from traces (span above 75th percentile of normal) (SV.A.1). Split 80/10/10 plus leave-one-fault-location-out.

## Modalities
Metrics are the model input; traces only produce labels (and are needed for supervision).

## LLM
None.

## Baselines
GrangerMV, PC, Microscope, NOTEARS, GOLEM, DYNOTEARS, each with SR or FC aggregation; call graph used as prior (SV.A.3).

## Metrics
Normalized SHD = (E+M+R)/T, precision, recall, F1 on directed edges (SV.A.2); fault-origin accuracy 0.976 (SV.B.5). No seeds, CI or significance.

## Main results
Figs 5-6 (plots, values not in text): beats best baseline beyond about 100 labeled batches; F1 matches baselines with about 60 labels. Fig 8: disentanglement helps on unseen fault locations. Inference 0.56 s per batch on an i7 CPU (SV.B.4).

## Artifact availability
None stated for code. Dataset B is an existing public set [62]; Dataset A not stated as released.

## Limitations / failure modes
Label cost, O(S^3) acyclicity penalty, only CPU-hog faults; heuristic trace labels, unobserved confounders; far-from-root edges poorly estimated (SVI.B-C, SV.B.5).

## Missing telemetry
Not tested directly; unavailable or sampled traces named as a label-quality risk (SVI.B); metric gaps mentioned only as motivation (SIII).
