## Question
Can root cause localization (RCL) for microservice IoT apps at the edge run decentrally, cutting localization time without losing accuracy? (Abstract, SI)

## Method
Cluster edge devices by communication/colocation (Alg. 1, threshold tau via TPE); run Personalized PageRank (PPR) inside each cluster; for cross-cluster propagation, clusters exchange an average anomaly score (JXP-style p2p approximation) and aggregate rankings (SIII-C). New anomaly score = correlation within BIRCH anomalous-metric clusters + incoming anomalous-edge latency correlation (SIII-A, eq. 1-3). Anomaly detection: BIRCH, beta 0.07 (SIV-A).

## Data and systems
MicroCERCL public cloud-edge dataset: 81 microservices, SockShop, Hipster, Bookinfo, AI-Edge; ChaosMesh and tc faults. 383 scenarios used: 237 SH, 146 HH (SIV-A).

## Modalities
Metrics (node/edge anomaly scoring) plus traces (topology graph) (SII-B, SIV-A). No logs.

## LLM
None.

## Baselines
Own centralized PPR; MicroCERCL GNN numbers quoted from its paper, not re-run (SIV-B, Table II). No other RCL baseline.

## Metrics
Acc@k (k=1,2,3,5,10), MAR, MRR; average and total time-reduction percentage with formulas (SIV-B).

## Main results
- Decentralized HH Acc@1 0.5616, MRR 0.7295, time -17.41% (avg) / -21.34% (total); SH Acc@1 0.6076, MRR 0.7733, -33.22% / -33.59% (SIV-B, Table III).
- Centralized PPR HH Acc@1 0.4315; MicroCERCL GNN HH 0.632 (SIV-B, Table II): GNN stays better at top-1.
- Single-cluster 311/383, multi-cluster 72/383; multi-cluster time gain only 2.77-28.79% (SIV-C, Table IV).

## Limitations / failure modes
Assumes communication-aware placement as secondary objective; does not generalise to frequent bidirectional inter-cluster communication (SV). Gains drop in multi-cluster cases (SIV-C). No repetition or significance test; one dataset.
