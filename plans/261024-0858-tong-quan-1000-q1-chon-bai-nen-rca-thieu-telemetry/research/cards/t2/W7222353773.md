# W7222353773 - Evaluating Self-Reflective LLM Agents for Autonomous Kubernetes Troubleshooting

- Version read: publishedVersion (IEEE Access 2026, 19 pp); text sha256 0e9f1875e138b47f787a80173f155d112f480f49f136d69851abad55039f02f3
- Reader: r1. F_total 15, t2_gate 0 (not an RCA/localization method).

## Question
Does Reflexion (one verbal self-reflection between two attempts) improve LLM agents on Kubernetes misconfiguration remediation beyond a plain verified retry? (Abstract, RQ1-4 §I)

## Method
Actor (Claude Agent SDK, kubectl) + deterministic evaluator + reflection module + episodic memory; 3 configs (one-shot, two-try, Reflexion) plus post-hoc feedback-only, reflection-with-reason, self-verification and windowed-baseline controls (§III-A, §III-B).

## Data and systems
10 hand-built Minikube fault scenarios (8 single, 1 double, 1 triple fault), Table 3; 1,500 runs = 5 models x 10 scenarios x 3 configs x 10 reps (§III-A).

## Modalities
kubectl state: pod status, events, logs, endpoints (§III-B). No metrics/traces pipeline.

## LLM
Claude 3 Haiku, 3.5 Haiku, Haiku 4.5, Sonnet 4.5, Opus 4.5 via API; Actor (diagnose + repair) and Reflector (§III-E).

## Baselines
Internal only: one-shot and two-try; no external RCA baselines (Table 4).

## Metrics
Success rate SR_c = (1/N_c) sum I(success), Eq.1; Wilson 95% CI, chi-square, Cohen h, mixed-effects logistic and GEE (§III-F).

## Main results
- Overall SR 38.6% -> 68.4% (two-try) -> 69.2% (Reflexion) (§IV-A, Table 5).
- Reflexion -2.0 pt single-fault, +12.0 pt on each of the two multi-fault cases, CIs overlap (§IV-E, Table 10).
- Feedback-only control 76.4% vs Reflexion 26.0% on multi-fault; reflection given the reason 79.1% (abstract, §IV-F).

## Artifact availability
github.com/mmerts/thesis-sdk: per-run JSON, SQLite, prompts, scenario scripts, evaluator; no license or run guide mentioned (Data and Code Availability).

## Limitations / failure modes
10 scenarios, only 2 multi-fault; single-node Minikube; single model family; reflection prompt lacked evaluator reason in main matrix (§III-B, §V-E).

## Missing telemetry
Not treated; closest is withholding the evaluator's failure reason from the reflector (§III-A, §IV-F), an information-feedback ablation, not telemetry loss.

## Fit note
Remediation task with no component ranking and no AC@k; useful only as background on retry vs reflection for an LLM agent.
