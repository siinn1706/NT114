## Question
Automatically find root causes and fixes for PostgreSQL anomalies with an LLM within minutes.

## Method (S4-7)
Offline knowledge extraction from documents; prompt generation with knowledge and tool matching; tree-search diagnosis with backtracking; multi-expert collaboration with cross-review; optional fine-tuning of 13B models (S8.5).

## Data and systems
Self-made micro benchmark of 539 simulated anomalies, six application types, ten root-cause types on PostgreSQL 12.5 (Table 1, S8.1-8.2); ten test cases per application.

## Modalities
Metrics (Prometheus), query statistics (pg_stat_statements), alerts, query logs, documents; accessed through tool APIs (S3 Fig 4, S4.2, S5.2).

## LLM
GPT-4-0613 and gpt-3.5-turbo-16k, temperature 0; Llama 2, CodeLlama, Baichuan 2 (13B) fine-tuned on 2819 samples with one A100 (S8.1, S8.5).

## Baselines
HumanDBA (2 years exp.), DNN, DecisionTree, plain GPT-4, plain GPT-3.5 (S8.1). Ablations NoKnowledge / NoTreeSearch / SingleLLM.

## Metrics
Acc = (Ac - sigma*Aw)/Aa (sigma 0.1, max 4 causes) and HEval, human-judged (S8.2).

## Main results
Table 2: D-Bot(GPT-4) single-cause Acc 0.754 / HEval 0.500, multi-cause 0.655 / 0.669; plain GPT-4 0.351 / 0.39 and 0.105 / 0.151; HumanDBA 0.955 / 0.720 and 0.487 / 0.806. Fine-tuned 13B models near GPT-4 on 27 cases (Fig 11, S8.5).

## Artifact availability
PVLDB statement under the abstract: code, data, report at github.com/TsinghuaDatabaseGroup/DB-GPT; license and run guide not in text.

## Limitations / failure modes
Hallucination and early stop motivate the design (S1); fine-tuned models generalize poorly to rare causes such as delete (Finding 5, S8.5). No limitations section.

## Missing telemetry
Not studied. The agent calls different tools, so a source could be withheld, but there is no such experiment.
