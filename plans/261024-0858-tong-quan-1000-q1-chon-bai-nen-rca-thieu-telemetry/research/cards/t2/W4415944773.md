## Question
Reduce LLM hallucination and error propagation in multi-step RCA by splitting the work among specialised agents with retrieval and validation (Abstract; Introduction).

## Method
Four agents: RCA (orchestrator, input parsing), Retrieval (hybrid keyword+semantic case retrieval, LLM "root cause inversion" into cause-to-symptom index, Algorithm 1), Validation (LLM turns symptoms into indicators, tools read runtime data, embedding similarity gives match score, Algorithm 2), Report (Method; "Validation Agent" section).

## Data and systems
Nezha dataset (OnlineBoutique 56 faults, TrainTicket 45 faults, Table 1); 50% of instances become the historical case base, 50% evaluation (Evaluation > Datasets). Private "Power monitoring" dataset (ICT + electrical faults, Table 2), partly synthetic telemetry streams.

## Modalities
Logs, metrics, traces from pre-processed stored telemetry; input to the pipeline is a single observable metric anomaly plus free-text alert (Evaluation > Datasets).

## LLM
QwenMax as default; also Qwen-QwQ, LLaMA3.3-70B, DeepSeek (Table 5, Power dataset only). Roles: parsing, root cause inversion, data-to-text, difference generation.

## Baselines
CoT, RAG, RCACopilot, RCAgent, mABC (Evaluation > Baselines).

## Metrics
Accuracy, precision, recall, F1 over fault classes, described in words only; averaging scheme and denominators not given (Evaluation > Baselines, last paragraph). No AC@k or MRR.

## Main results
- Nezha: Acc 0.958, F1 0.952 vs best baseline RCACopilot F1 0.748 (Table 3).
- Power: Acc 0.843, F1 0.828 (Table 3).
- Ablation: w/o Retrieval Agent F1 0.295 on Nezha; w/o Validation 0.681; w/o multi-agent 0.716 (Table 4).
- Case count k: best at 5 (F1 0.828), drops at 10/20 (Table 6).
- Single run per setting, no CIs or significance tests.
