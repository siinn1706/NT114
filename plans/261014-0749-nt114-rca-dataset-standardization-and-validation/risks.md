# Risks and recovery

| ID | Risk | Likelihood / impact | Detection | Mitigation | Recovery |
|---|---|---|---|---|---|
| S1 | Label leakage into prompts, evidence, retrieval or Jev | Medium / critical (invalidates results) | T16 canary and permutation tests; denylist and path scans in `audit` | Zone separation, opaque uids, train-only store, label-agnostic masking operator | Fail the build; fix; rebuild evidence; any results produced with leaked inputs are discarded and re-run |
| S2 | Wrong timestamp alignment (units, offsets, time zones) | High for Nezha and AIOps2025 / high | `TS_*`, `ANCHOR_OUTSIDE_WINDOW`, coverage findings; phase-02 profile | One documented rule per source; never guess silently | Mark modality `corrupted` or incident `QUARANTINE`; adapter PATCH; `normalize --incident` rebuild |
| S3 | Service identity collisions or wrong pod → service mapping | Medium / high | `SERVICE_ID_COLLISION`, `ROOT_NOT_CANDIDATE` | Explicit map, alias file, idempotence check | Add alias with reason; rebuild affected incidents |
| S4 | Silent data loss during normalization | Medium / high | Row counts per member in the run ledger vs. source row counts in the profile | Every dropped row counted in a finding | Fix adapter; rebuild |
| S5 | Disk exhaustion from extraction plus canonical copies | Low (787 GB free) / medium | `status` reports sizes; budget check before `extract` | AIOps2025 is the only large extraction (~12 GB); RCAEval streamed from zips | Delete `work/extract/` after a successful build; it is rebuildable |
| S6 | Memory blow-up on large CSV members | Medium / medium | Profile records the largest member; peak RSS in the run ledger | Streaming readers, `chunk_rows`, `max_workers: 2` | Lower `chunk_rows` / workers; per-incident resume |
| S7 | Non-determinism across machines (pandas/pyarrow versions) | Medium / medium | `content_sha256` comparison after transfer (T21) | Lock file with identical pyarrow/pandas/numpy on both machines; hashes over a canonical row serialization, not IPC or file bytes | Install the locked versions; re-verify |
| S8 | Windows-specific failures (encoding, path length, reserved names) | High without fixes / medium | T04, T05, T20 on Windows; T21 on Linux | UTF-8 everywhere, short relative paths, name rules | Move `RCA_DATA_HOME` to a short path; fix offending writer |
| S9 | A dataset fails its promotion gate (Nezha timestamps, RCA100 entities, AIOps2025 TZ) | Medium / medium (fewer A datasets) | Phase-02 gate report | Gates and fallbacks decided in advance (compatibility matrix) | Proceed with remaining A sets; record the decision; no pipeline change |
| S10 | Pooling incompatible labels into one metric | Medium / high (scientific) | Report generator refuses pooled tables across `label_granularity` | Per-incident `eval_tier` and granularity | Regenerate tables per stratum |
| S11 | Repeated injections or overlapping windows leaking across splits | High without grouping / high | T18; `audit` checks that no `group_id` spans splits | Union-find grouping | Rebuild split (new id); old manifest remains for audit |
| S12 | Licence or redistribution breach (RCA100 answer key, BY-NC sets) | Low / high | `bundle.json` lists licences; export refuses `--public` | Bundles are private transfers between the owner's machines | Delete the bundle copy; notify per licence terms |
| S13 | Existing behaviour regresses in `run_grid` / `evidence` | Medium / medium | T01, T02, T10, T19 | Compatibility layer instead of rewrites; legacy path kept | Revert the phase-11 commit; legacy configs still run |
| S14 | Scope too large for 1–2 people | Medium / medium | Phase effort tracking | Phases are independently shippable; B adapters (phase 08) can follow A integration | Ship phases 01–07, 09–12 for A datasets first; phase 08 after |
| S15 | Pre-training contamination of public datasets | Unknown / medium (scientific) | Not detectable by data checks | First-public dates already in provenance; recorded per dataset in reports | Report as a limitation; prefer newest sets (AIOps2025 2026, RCA100) for headline checks |
